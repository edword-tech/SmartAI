# 国产卡兼容性说明

本文说明 Unified Resource Manager 对国产 GPU/NPU 的兼容程度与扩展方式。

## 一、当前已支持

### 1. 华为昇腾 (Ascend)

| 项目 | 说明 |
|------|------|
| **类型** | NPU，在系统中作为 `npu` 资源类型与 GPU 并列 |
| **对接方式** | Ascend-Virtual-Service 的 **flexnpud**（Hypervisor） |
| **适配层** | `adapters/npu/npu_adapter.go`：调用 flexnpud HTTP API 做设备注册/注销、状态与指标查询 |
| **设备发现** | `core/cluster/npu_device_discoverer.go`：通过 flexnpud 或节点标签发现 NPU；可扩展为按 `node.Address` 调 flexnpud API / dcmi |
| **规格示例** | `npu.910b3.8g.infer`、`npu.910b3.16g.train`（见 `cmd/main.go` initResourceFlavors） |

部署时需部署 **Ascend-Virtual-Service**（含 flexnpud），并将 `NPU_HYPERVISOR_ENDPOINT`、`NPU_ACL_SERVER_ENDPOINT` 指向对应服务。

## 二、架构上的扩展方式（其他国产卡）

系统通过 **设备发现接口** 和 **资源类型** 抽象 GPU/NPU，新增国产卡可按以下方式接入。

### 1. DeviceDiscoverer 接口

- 定义：`core/cluster/device_discoverer.go`  
  - `DiscoverGPUs(ctx, node) ([]*GPUInfo, error)`  
  - `DiscoverNPUs(ctx, node) ([]*NPUInfo, error)`

- **GPU 类国产卡**（摩尔线程 MTT、海光 DCU、景嘉微等）  
  - 实现一个 `DeviceDiscoverer`，在 `DiscoverGPUs` 中调用厂商 SDK/API/device-plugin 获取设备列表，填充 `GPUInfo`（DeviceID、Model、TotalMemory、TotalCores）。  
  - 在 `main.go` 中替换或组合进 `ClusterManager` 的 `SetDeviceDiscoverer(...)`（例如与现有 `HybridDeviceDiscoverer` 组合，或新写一个“多 GPU 厂商”发现器）。

- **NPU 类国产卡**（除昇腾外，其他 NPU 若统一走“NPU”资源类型）  
  - 实现 `DeviceDiscoverer`，在 `DiscoverNPUs` 中调用厂商管理接口，填充 `NPUInfo`。  
  - 若厂商有独立 Hypervisor/API，可参考 `NPUAdapter` 新增一个 Adapter，再在发现器或资源池中调用该 Adapter。

### 2. 资源类型与调度

- 当前资源类型：`gpu`、`npu`（见 `core/pool/resource_pool.go`）。  
- 国产 **GPU** 建议归为 `gpu`，与现有 GPU 池、规格、调度逻辑复用。  
- 国产 **NPU** 建议归为 `npu`，与现有 NPU 池、规格、调度逻辑复用；若未来需要区分厂商，可在 `Labels` 或 `ResourceFlavor` 上增加厂商/型号标识，调度器按标签过滤即可。

### 3. 规格与前端

- 在 `cmd/main.go` 的 `initResourceFlavors` 中为国产卡增加 `ResourceFlavor`（如 `gpu.mtt-s80.32g.train`、`npu.xxx.16g.infer`）。  
- 前端已按 `gpu` / `npu` 展示，无需改类型；若有厂商/型号展示需求，可用 flavor 的 `Model` 或 `Labels` 区分。

## 三、国产卡兼容程度汇总

| 厂商/芯片 | 资源类型建议 | 当前支持 | 扩展方式 |
|-----------|--------------|----------|----------|
| **华为昇腾 (Ascend)** | NPU | ✅ 已支持 | 使用现有 NPU 适配器 + flexnpud，见上文 |
| **摩尔线程 (Moore Threads, MTT)** | GPU | 需扩展 | 实现 DeviceDiscoverer（DiscoverGPUs），调用 MTT 驱动/管理 API；注册 GPU 规格 |
| **海光 (Hygon) DCU** | GPU | 需扩展 | 实现 DeviceDiscoverer（DiscoverGPUs），对接海光 ROCm/管理接口；注册 GPU 规格 |
| **景嘉微 (Jingjiawei)** | GPU | 需扩展 | 同上，实现 DiscoverGPUs + 规格注册 |
| **壁仞 (Biren)** | GPU | 需扩展 | 同上 |
| **其他 NPU（非昇腾）** | NPU | 需扩展 | 实现 DeviceDiscoverer（DiscoverNPUs）及可选 NPU Adapter；注册 NPU 规格 |

“当前支持”仅表示本仓库已提供对接路径或现成实现；具体芯片是否可用还依赖厂商驱动、固件与运行环境。

## 四、开发时注意事项

1. **后端先启动**：前端开发时若遇 `/api/v1/*` 报 **ECONNREFUSED**，请先在本机启动 Unified Resource Manager 后端（如 `make run` 或 `go run ./cmd/main.go -port 8080`），并确保 Vite 代理目标（默认 `http://127.0.0.1:8080`）与后端一致。  
2. **国产卡驱动与权限**：设备发现或 Adapter 若需访问厂商 SDK/设备节点，需在部署环境中安装对应驱动并保证进程有访问权限。  
3. **多厂商共存**：通过 `HybridDeviceDiscoverer` 或自定义“组合发现器”可在同一集群中同时支持 NVIDIA GPU、昇腾 NPU 与其它国产 GPU/NPU。

以上为当前国产卡兼容程度与扩展方式说明；新增厂商时以实现 `DeviceDiscoverer` 和（按需）对应 Adapter 为主即可接入现有调度与前端。
