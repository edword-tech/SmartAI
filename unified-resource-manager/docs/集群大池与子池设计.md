# 集群大池与子池设计

## 一、需求概述

- **节点 GPU 聚合成大池**：将多节点、多块 GPU 合并成一个逻辑上的「大池」，用于承载多个大模型集群服务。
- **大模型集群调度**：在大池上调度多个多卡任务（每个任务可占用多卡，如 4 卡、8 卡推理/训练集群）。
- **大池内切分/池化**：在大池内再划分子池，支持按配额、按租户或按切分配置（vGPU 等）进行池化。

## 二、模型与 API

### 2.1 集群池（Cluster Pool，大池）

- **含义**：一个逻辑大池，由一组节点（或物理池）聚合而成，分配时仅从这些节点/池中选资源。
- **存储**：`ClusterPoolSpec`（id, name, type, node_ids, pool_ids）。
- **API**：
  - `GET /api/v1/cluster-pools` — 列表
  - `POST /api/v1/cluster-pools` — 创建
  - `GET/PUT/DELETE /api/v1/cluster-pools/{id}` — 查/改/删
  - `GET /api/v1/cluster-pools/{id}/info` — 聚合的池信息（总/可用/已用卡数、显存等）
  - `GET /api/v1/cluster-pools/{id}/resources` — 该大池内资源列表（可按 state 等过滤）
  - `POST /api/v1/cluster-pools/{id}/allocate` — 从大池分配（请求体与 `/pools/{poolId}/allocate` 一致，内部会加上节点约束）

**分配约束**：`AllocationRequest` 支持 `constrain_node_ids`、`constrain_pool_ids`。从集群池分配时，后端自动填入该大池的 `node_ids`（及可选的 `pool_ids`），底层 GPU/NPU 池在选资源时只从这些节点/池中选。

### 2.2 子池（Sub Pool，大池内切分）

- **含义**：挂在一个「父池」上的逻辑子池，父池可以是集群池或物理池；子池带配额（最大卡数、最大显存），可选关联切分配置（算力质量中的 SlicingConfig）。
- **存储**：`SubPoolSpec`（id, name, parent_cluster_pool_id 或 parent_pool_id, quota_max_count, quota_max_memory_gb, slice_config_id）。
- **用量**：`SubPoolManager` 维护每个子池的已用 count / memory_gb，分配前检查配额，分配成功后增加用量。
- **API**：
  - `GET /api/v1/sub-pools` — 列表（可选 query：`cluster_pool_id`、`parent_pool_id`）
  - `POST /api/v1/sub-pools` — 创建
  - `GET /api/v1/sub-pools/{id}` — 详情
  - `DELETE /api/v1/sub-pools/{id}` — 删除
  - `GET /api/v1/sub-pools/{id}/usage` — 当前用量
  - `POST /api/v1/sub-pools/{id}/allocate` — 从子池分配（先校验配额，再按父池类型走集群池或物理池分配，成功后更新用量）

### 2.3 大模型集群（多卡任务）与调度

- **多卡任务**：沿用现有「任务」模型，`resource_req.count` > 1 即表示多卡（如 4 卡、8 卡）。任务提交时可指定从某集群池分配（见下）。
- **调度**：现有调度器按 `resource_req` 选资源；若需「仅从某大池调度」，可在提交任务时在 `labels` 中带 `cluster_pool_id`，调度器在向资源池发起分配时带上对应的 `constrain_node_ids` / `constrain_pool_ids`（与 `POST /cluster-pools/{id}/allocate` 行为一致）。当前实现中，用户也可直接调用 `POST /api/v1/cluster-pools/{id}/allocate` 得到多卡分配结果，再与任务绑定。

## 三、实现要点

### 3.1 分配请求约束

- **core/pool/resource_pool.go**  
  - `AllocationRequest` 增加 `ConstrainNodeIDs []string`、`ConstrainPoolIDs []string`。  
  - `AllocateAny`：若指定了 `ConstrainPoolIDs`，只从这些物理池中选；选池后仍把完整 `req`（含 `ConstrainNodeIDs`）传给该池的 `AllocateResources`。

### 3.2 适配器层

- **adapters/gpu**、**adapters/npu**：在 `findAvailableResources` 中，若 `req.ConstrainNodeIDs` 非空，只保留 `r.NodeID` 在该集合内的资源。

### 3.3 集群池聚合信息

- **core/pool/cluster_pool.go**：`ClusterPoolManager.GetPoolInfoFromUnified` 根据集群池的 `node_ids`（及可选的 `pool_ids`）从统一资源池中过滤资源并聚合出 `PoolInfo`（总/可用/已用卡数、显存等）。

### 3.4 子池配额

- **core/pool/sub_pool.go**：`SubPoolManager` 维护 `usage`（count、memory_gb）；`CheckQuota`、`AddUsage`、`SubUsage` 用于分配前校验与分配/释放后更新。释放时若需回扣用量，需在释放链路中根据 allocation 归属调用 `SubUsage`（当前释放接口若未带 sub_pool_id，可由后续扩展记录 allocation → sub_pool 的映射再扣减）。

## 四、使用示例

### 创建大池并分配 4 卡（大模型集群）

```bash
# 创建集群池（大池）：节点 node-gpu-1、node-npu-1 的 GPU 聚合成一个池
curl -X POST http://localhost:8080/api/v1/cluster-pools \
  -H "Content-Type: application/json" \
  -d '{
    "id": "llm-cluster-pool-1",
    "name": "大模型集群池1",
    "type": "gpu",
    "node_ids": ["node-gpu-1", "node-hybrid-1"]
  }'

# 查看大池聚合信息
curl http://localhost:8080/api/v1/cluster-pools/llm-cluster-pool-1/info

# 从大池分配 4 卡给一个推理集群
curl -X POST http://localhost:8080/api/v1/cluster-pools/llm-cluster-pool-1/allocate \
  -H "Content-Type: application/json" \
  -d '{
    "task_id": "infer-1",
    "task_type": "inference",
    "resource_type": "gpu",
    "count": 4,
    "memory_gb": 24,
    "cores": 100,
    "priority": 5,
    "timeout": "24h"
  }'
```

### 在大池内创建子池并分配

```bash
# 创建子池：配额最多 8 卡、256GB 显存
curl -X POST http://localhost:8080/api/v1/sub-pools \
  -H "Content-Type: application/json" \
  -d '{
    "id": "team-a-pool",
    "name": "团队A子池",
    "parent_cluster_pool_id": "llm-cluster-pool-1",
    "quota_max_count": 8,
    "quota_max_memory_gb": 256
  }'

# 从子池分配 2 卡
curl -X POST http://localhost:8080/api/v1/sub-pools/team-a-pool/allocate \
  -H "Content-Type: application/json" \
  -d '{
    "task_id": "task-1",
    "task_type": "training",
    "resource_type": "gpu",
    "count": 2,
    "memory_gb": 40,
    "cores": 100,
    "priority": 5,
    "timeout": "72h"
  }'

# 查看子池用量
curl http://localhost:8080/api/v1/sub-pools/team-a-pool/usage
```

## 五、与算力质量切分的结合

- 子池的 `slice_config_id` 可关联算力质量中的 **SlicingConfig**（如 vGPU 切分规格）。后续在从子池分配时，可先按该切分配置解析出「等价卡数/显存」，再与 `quota_max_count` / `quota_max_memory_gb` 一起做配额校验，并下发给底层池时带上切分参数。
